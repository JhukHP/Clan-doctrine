# PROJECT.md

# Project Overview

## Project Name

STALZONE Clan Playbook Framework

---

# Mission

Develop a complete operational framework for managing, training and continuously improving a competitive STALZONE clan.

The framework must transform individual players into coordinated teams capable of achieving stable competitive results through organization, standardized procedures and continuous improvement.

The project is intended to become a long-term knowledge base rather than a static document.

---

# Project Goals

The framework should:

- improve teamwork;
- improve communication;
- reduce dependency on individual players;
- simplify onboarding of new members;
- improve leadership quality;
- create repeatable training methods;
- preserve organizational knowledge;
- survive roster changes;
- survive leadership changes;
- remain maintainable over multiple game seasons.

---

# Scope

The repository contains documentation related to:

- clan organization;
- leadership;
- communication;
- squad management;
- training methodology;
- standard operating procedures (SOP);
- mentoring;
- after action reviews;
- continuous improvement;
- seasonal preparation;
- organizational standards.

The repository is NOT intended to document game mechanics.

Game-specific mechanics should only appear when necessary to explain organizational decisions.

---

# Project Philosophy

The framework is based on several fundamental ideas.

## Organization wins over individual skill.

The objective is not to create stronger individual players.

The objective is to create stronger teams.

---

## Stable processes outperform improvisation.

Successful actions should become documented procedures.

---

## Standards reduce uncertainty.

Every player should know:

- what to do;
- why;
- when;
- how.

---

## Documentation exists to improve performance.

Documentation is never written for its own sake.

Every document must provide practical value.

---

## Continuous improvement.

The framework is never considered finished.

Every season provides new information.

Every season may improve the documentation.

---

# Clan Organization Model

The clan is organized around stable four-player squads.

Each squad normally consists of:

- Squad Leader
- Leader Partner
- Master
- Master Partner

The squad is the smallest independent tactical unit.

Whenever possible squads remain stable over long periods.

---

# Reserve Philosophy

Reserve players are NOT attached to individual squads.

The reserve is universal.

Every reserve player must be capable of joining any squad with minimal preparation.

Reserve players follow the same organizational standards as the main roster.

---

# Command Structure

The Caller coordinates squads.

The Caller issues objectives.

The Caller does not micromanage squad execution.

Each Squad Leader is responsible for tactical execution.

The squad decides HOW to complete the assigned objective.

---

# Training Philosophy

Training is divided into several levels.

Individual skills.

↓

Pair coordination.

↓

Squad coordination.

↓

Inter-squad cooperation.

↓

Full clan coordination.

Training should always progress from simple to complex.

---

# Pair System

Permanent pairs are preferred.

Pairs develop:

- trust;
- anticipation;
- communication efficiency;
- mutual support.

Pairs may temporarily separate when tactical situations require it.

After completing the task they regroup whenever practical.

---

# Rotation Philosophy

Rotation is mandatory.

Every clan member should participate in competitive matches whenever possible.

The framework should support player development rather than protecting fixed lineups.

---

# Offseason

The offseason exists to:

- train future leaders;
- experiment with tactics;
- test new SOPs;
- evaluate reserve players;
- rotate responsibilities;
- improve documentation.

The competitive season prioritizes stability.

The offseason prioritizes improvement.

---

---

# Decision Making

Major organizational decisions should be documented inside DECISIONS.md.

Documentation should explain not only WHAT was decided but WHY.

---

# Writing Style

Documentation should be:

- concise;
- professional;
- practical;
- structured;
- maintainable.

Avoid unnecessary verbosity.

Avoid motivational language.

Avoid management clichés.

---

# Long-Term Vision

The framework should eventually become the primary operational knowledge base of the clan.

New leaders should be able to understand how the organization functions without relying on verbal explanations.

Organizational knowledge should remain inside the repository rather than inside individual people.
